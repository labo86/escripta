# Naming Rules

## Goals

- Make file and symbol names predictable.
- Reduce ambiguity in specs and code reviews.

## Rules

- Prefer names that describe behavior, not implementation detail.
- Keep acronyms and abbreviations to existing project conventions.
- Name specs by outcome, not by ticket number only.
- Use singular names for one conceptual unit and plural names for collections.
- Keep method names action-oriented when they trigger work.
- Keep filenames stable unless renaming clearly improves discoverability.

## Spec Filenames

Prefer:

- `YYYY-MM-DD-short-name.md`
- `config-local-by-path.md`
- `config-writeinfiles-underscore.md`
